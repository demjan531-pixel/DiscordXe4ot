# Invokyr Tracker 2

Discord-бот для команды, которая переносит Invokyr в Roblox. Он ведёт задачи, выдаёт заранее разрешённые рабочие роли и собирает прогресс в одном канале. Бот не читает старую или новую переписку. Задачи из чата команда переносит сама.

## Как пользоваться

| Команда | Что делает |
| --- | --- |
| `/task create` | Создаёт задачу с направлением, сроком, описанием и приоритетом. Можно назначить роль, конкретного человека или обоих. |
| `/task list` | Показывает задачи с фильтрами по роли, исполнителю, направлению, статусу или приоритету. Страницы можно переключать кнопками под ответом. |
| `/task mine` | Показывает задачи, где текущий участник указан исполнителем; список тоже листается кнопками. |
| `/task claim` | Позволяет участнику нужной роли взять на себя свободную задачу. Бот не назначает одну задачу двоим. |
| `/task show` | Открывает карточку задачи по номеру. |
| `/task edit` | Меняет название, направление, описание, срок, приоритет, роль или исполнителя. |
| `/task status` | Меняет статус на «К выполнению», «В работе», «На проверке», «Заблокировано» или «Готово». Для блокировки нужна причина. |
| `/task history` | Показывает, кто менял задачу и какие действия выполнял. |
| `/task delete` | Удаляет задачу после явного подтверждения. Удалить её может автор или руководитель; запись и журнал остаются в базе для аудита. |
| `/progress` | Считает закрытые задачи, просрочки и блокировки по проекту, направлению или роли. Процент означает долю закрытых задач, а не готовность игры. |
| `/role list`, `/role grant`, `/role remove` | Показывают список управляемых ролей, выдают и снимают разрешённую роль. |

**Пример для команды.** Руководитель создаёт задачу «Собрать прототип ближнего боя», выбирает «Механики», высокий приоритет, роль `Gameplay` и срок. Участник с ролью `Gameplay` вызывает `/task claim` с номером задачи, а потом отправляет работу на проверку через `/task status`. Если он ждёт анимацию, выбирает «Заблокировано» и пишет причину. Когда задача закрыта, это видно в `/progress`.

Частные ответы на команды видит только вызвавший их участник. Это не делает задачи секретными: участники, которым доступны команды, могут открыть задачи через список или карточку. Для закрытого проекта ограничь доступ к каналу и при необходимости задай `TEAM_ROLE_ID`.

## 1. Подключи Discord

Если бот из первой версии уже установлен, используй то же приложение и тот же токен. Новый токен нужен только при первой настройке или если старый скомпрометирован.

1. Открой [Discord Developer Portal](https://discord.com/developers/applications), нажми **New Application**, назови приложение `Invokyr Tracker`.
2. Во вкладке **Bot** получи токен через **Reset Token**. Не отправляй токен в чат и не клади его в репозиторий. Если он утёк, сбрось его в Developer Portal.
3. Во вкладке **Installation** оставь **Guild Install** и **Discord Provided Link**. В **Default Install Settings → Guild Install** проверь разрешения `applications.commands` и `bot`. Для работы в канале нужны **View Channel** и **Send Messages**; по возможности выдавай их только в канале проекта.
4. По ссылке установки человек с нужными правами выбирает **Add to server** и конкретный сервер. Убедись, что в настройках приложения не указан **Interactions Endpoint URL**: эта версия принимает команды через Gateway, а не через входящий HTTP.
5. **Administrator**, **Read Message History**, **Message Content**, **Server Members** и **Presence** не нужны. Чтобы бот мог выдавать и снимать роли, отдельно настрой **Manage Roles** по инструкции ниже. Для одного лишь трекера его не включай.

Справка: [первый бот Discord](https://docs.discord.com/developers/quick-start/getting-started) и [разрешения и иерархия Discord](https://docs.discord.com/developers/topics/permissions#permission-hierarchy).

### Настрой управление рабочими ролями

Здесь есть два отдельных действия: `team_role` назначает роль задаче и даёт участникам этой роли право взять её через `/task claim`; `/role grant` и `/role remove` выдают или снимают роль участнику. Назначение роли задаче само по себе не выдаёт её людям.

1. Создай обычные рабочие роли, например `Gameplay`, `Maps`, `UI` и `QA`. Для выдачи ботом у такой роли должны быть выключены **все** собственные серверные права; у роли также не должно быть явно разрешённых или запрещённых прав на каналах и категориях. Обычные права пользователей можно отдельно настроить на `@everyone` или на существующей роли доступа.
2. В Discord включи **Настройки пользователя → Расширенные → Режим разработчика**, затем скопируй ID рабочих ролей. Вставь их через запятую в `ROLE_MANAGE_IDS` файла `.env`. Не добавляй роль владельца, роль руководителя проекта или роли модераторов.
3. Дай боту **Manage Roles** на сервере и поставь его служебную роль **выше** разрешённых рабочих ролей, но **ниже** ролей администрации. Не поднимай бота выше, чем нужно. Если автоматическая выдача ролей больше не нужна, убери **Manage Roles** и очисти список.
4. Если выдачу ролей нужно делегировать, укажи отдельную роль руководителя проекта в `MANAGER_ROLE_ID`. Выдавать и снимать разрешённые роли может владелец сервера или участник с этой ролью и правом **Manage Roles**. Руководитель должен иметь Discord-разрешение **Manage Roles**; бот проверяет полномочия и порядок ролей. Команда не меняет роли вызывающему её участнику, владельцу сервера или ботам — себе роль назначь вручную в Discord.
5. Проверь `/role list`: он показывает список, разрешённый в `ROLE_MANAGE_IDS`. Для выдачи вызови `/role grant`, укажи участника и роль; для снятия — `/role remove`. Если нужной роли в выборе нет, добавь её ID в `.env` и перезапусти бота. Обычный участник не может выдавать роли.

**Что защищает доступ.** Discord может выдавать права и через настройки конкретных каналов. Если Discord скрывает от бота хотя бы один канал и бот не может проверить его настройки, он откажется выдавать и снимать роли. Не открывай боту закрытые каналы ради этого: меняй роли вручную в настройках Discord. Назначение задач на роль продолжит работать. Одно совпадение имени роли не даёт полномочий: используй точные ID.

Изменять задачу может автор, руководитель или текущий исполнитель. Если задача закреплена за ролью, исполнителю должна по-прежнему быть выдана эта роль. Участник роли может взять свободную задачу, но не редактировать чужую только потому, что у него такая же роль.

## 2. Запусти на Windows

Распакуй архив и открой PowerShell в папке с `bot.py`. Используй Python 3.11 или 3.12.

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
if (!(Test-Path .env)) { Copy-Item .env.example .env }
notepad .env
```

В `.env` вставь токен **локально** вместо `PASTE_TOKEN_HERE`. ID сервера и канала заполнены под [ваш канал](https://discord.com/channels/1569734489335144578/1569734490220273768). Для испытания на другом сервере замени оба значения. Если перенёс старый `.env`, добавь недостающие параметры из `.env.example`, не перезаписывая файл с токеном.

```powershell
.\.venv\Scripts\python.exe bot.py
```

Когда бот зарегистрирует `task`, `progress` и `role`, открой указанный канал. Набери `/task create`, создай тестовую задачу на рабочую роль, зайди с участника этой роли и попробуй `/task claim`. Проверь `/task history` и `/progress`. Для удаления найди задачу через `/task list`, вызови `/task delete` с её номером и подтверди `confirm: Да`. Удалённые задачи исчезают из списков и сводок, а их история остаётся в базе. Команды работают в указанном канале, не в личных сообщениях и не в ветках.

Если команд нет, проверь правильность ID, разрешение **Use Application Commands** для своей роли и установку с областью `applications.commands`. Если команды есть, но выдача роли не работает, проверь `ROLE_MANAGE_IDS`, **Manage Roles** и положение ролей. Обычную задачу можно завести, не включая управление ролями.

## 3. Обнови первую версию без потери задач

1. Останови старый процесс: в PowerShell нажми **Ctrl+C** или останови worker на хостинге.
2. Сделай резервную копию прежней базы по пути из `DATABASE_PATH` (по умолчанию `data/tasks.sqlite3`). Делай копию, когда старая программа остановлена. Не публикуй файл: он содержит ID участников и содержание задач.
3. Распакуй новую версию в новую папку. Перенеси существующую базу и настройки `.env` в неё или укажи в `DATABASE_PATH` прежний абсолютный путь. Сверь новые настройки с `.env.example`. Не оставляй обе версии запущенными.
4. Запусти новую версию. Таблица обновится автоматически, номера, исполнители, сроки и статусы сохранятся. Для старых задач по умолчанию стоит обычный приоритет и нет роли. Журнал новой версии не восстанавливает изменения, сделанные до обновления.
5. Проверь несколько старых задач в `/task show`. Для возврата останови новую версию и восстанови копию отдельно; в старой копии не будет изменений, сделанных после обновления.

## 4. Сводка и работа 24/7

- По умолчанию сводка **выключена**. Чтобы публиковать её в канале проекта раз в день, задай `SUMMARY_ENABLED=1`, `SUMMARY_TIME=18:00` и нужный `PROJECT_TIMEZONE` (по умолчанию `Europe/Tallinn`). Бот не пишет личные сообщения и не пингует роли.
- Для круглосуточной работы запусти **один** экземпляр на постоянном хостинге, который не засыпает и перезапускает процесс после сбоев. Не запускай одновременно домашнюю и серверную копии. Токен храни в секретах хостинга.
- Подключи постоянный диск. Для приложенного `Dockerfile` монтируй диск в `/app/data` или задай путь на постоянном диске через `DATABASE_PATH`. Без постоянного диска при пересоздании контейнера задачи пропадут. Регулярно копируй SQLite-файл при остановленном боте.
- Даты в задачах можно вводить как `2026-12-01` или `01.12.2026`. Срок становится просроченным со следующего дня в часовом поясе проекта.

**Проверка на компьютере** после установки зависимостей: `python -m unittest -v`. Она не подключается к Discord. Один пробный запуск на реальном сервере всё равно нужен, чтобы проверить права и регистрацию команд.
